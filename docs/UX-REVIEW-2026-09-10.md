# 酒馆模式用户体验记录 · 2026-09-10

本轮建议先完善记忆显示、分支记忆继承和配置作用范围，再扩展新能力。基本角色对话、玩家设定、HTML 开场交互和编辑行动生成分支均已走通；当前最影响持续使用的是“记忆是否完整、能否读懂，以及换分支后能否找到原剧情”。

- 环境：用户指定的 Chrome 标签页，DSH 本地构建 `http://127.0.0.1:3080/`，工作区 `G:\Workspace\playground`，插件 package 版本 `0.10.0`。

- 使用既有角色「回声档案员·澄弦」进行两轮对话，再编辑第二轮行动生成一个分支。另用「【BanG Dream！】OurNotes 0826」验证 HTML 开场与线路切换，未向该角色发送新剧情。
- 保留的已开始会话：「酒馆体验测试｜林舟与雨燕徽章」「酒馆体验测试｜分支·取回徽章」。后者原自动标题为「星港回声复杂时间线演示」，为便于识别已手动重命名。
- 玩家测试设定：林舟（体验测试），成年旅行者，要求角色不代替玩家选择行动或说话。
- 未修改插件实现和 deepseek-harness，未重启或停止用户服务。角色库的默认选择已恢复为「回声档案员·澄弦」。

## F1 · P1 · 时间线遗漏合法的 fact 正文

**复现：** 原测试剧情完成首轮后台维护 → 时间线修订 1 → 打开 `ev-last-visitor-yuhui-7420-003`。

**实际：** 节点标题是 `mem yuhui last pre blackout visitor 7420 …`；详情只有时间、人物、地点和来源，没有中文事实正文。另一个停电事件同样显示内部键名。点击“编辑事件”后，现有记录却能正常显示 `fact` 及中文内容。

**证据：** 原会话的两条记录为 `value: { fact: "…" }`；分支四条记录为 `value: { text: "…" }`，后者在时间线显示正常。数据没有丢失。

**根因：** `src/event-maintenance.js:32-47` 允许开放结构的 value；`src/client/event-explorer-model.cjs:11-61` 的正文候选字段包含 text、summary 等但没有单数 fact，读取失败后退回内部 key。

**建议：** 兼容已存在的 fact 数据，统一新增记忆的可读标题/正文约定；对于其他合法结构，也应提供可展开的通用内容显示。先修显示兼容，再考虑规范新生成字段，避免只改后续输出而让旧数据继续空白。

**收尾复查：** 原会话已到修订 2、5 个事件、完成 2 次记忆整理，新增徽章事件等仍出现 `mem swift badge kept item` 一类内部键名。后台完成并未消除该显示问题。

**验收：** 同一份 `{fact: ...}` 记录在时间线、详情、搜索中均能呈现事实；`{text: ...}` 等既有结构继续正常。修改源模块后需按项目流程重建 client bundle。

## F2 · P1 · 分支遗漏切点前尚未完成的记忆整理

**复现：** 原剧情第一轮对话完成，但时间线仍修订 0、后台整理运行中 → 第二轮“编辑行动后重试” → 创建分支并完成生成。

**实际：** 分支包含第一轮聊天，玩家设定也正确；但分支事件队列只完成第二轮的维护，时间线只有第二轮的 4 条记忆，没有接续第一轮待完成的维护。父会话随后产生的事件不会同步进这个分支。

**根因：** `host.js:440-505` 复制切点前对话；`src/store.js:1702-1720`、`:1847-1915` 捕获并继承当时已提交的 binding/event/compat-chat 快照，不包含维护队列。`src/event-maintenance.js:558-565` 的队列按会话独立保存，`:699-712` 只恢复当前会话已有待办；自动触发监听新发生的 completed turn，不重放 seed 中的历史轮次。

**影响边界：** 第一轮聊天原文仍在，不能称为聊天丢失或立即失忆；缺的是事件文档、时间线以及对应的长期召回材料。首次周期整理（默认第 10 个完整回合）或手动 `/st-event-consolidate` 会把这段历史纳入维护上下文，可能补全，但不保证模型选择每一项事实。本轮未通过手动整理掩盖这个状态。

**建议：** 创建分支时识别切点前尚未完成整理的回合，为子会话补建维护任务；任务严格限定在分支切点内。已提交的事实快照继续继承，未提交的维护工作由子会话独立执行。

**验收：** 在父会话整理进行中、失败重试中分别分叉；子会话都能补齐切点前待整理的历史，不混入父会话切点后的新剧情，不重复提交同一维护工作。

## F3 · P1/P2 · 无绑定时默认编辑另一张角色的共享世界书

**复现：** 选「回声档案员·澄弦」（无默认世界书）→ 打开世界书标签。

**实际：** 下方“当前 Session 引用”是“不使用世界书”，上方却已经打开「【BanD Dream！】交织的乐章 0826」的 54 个条目，并提供保存/删除。两者独立的解释文字存在，但用户必须自行理解为什么当前剧情页面在编辑不相关内容。

**根因：** `client.cjs:2705-2730` 无当前书时回退 `worldbooks[0]`；保存与删除针对上方编辑目标，绑定是另一条独立操作。该行为可在纯前端修正，无需改变持久层引用模型。

**建议：** 首屏突出“本剧情正在使用的世界书”；没有绑定时显示空状态和“选择 / 新建并用于本剧情”。共享资源库编辑作为明确入口；编辑共享书时持续显示作用范围、引用情况，并突出已有的“复制到当前剧情再编辑”。

**验收：** 无绑定时不自动打开无关共享资源；选择编辑对象和改变本剧情绑定的反馈清晰；现有共享引用机制保持可用。

## F4 · P2 · 分支可创建，但缺少候选组织和回程导航

**实际：** “编辑行动后重试”立即打开新会话。原会话已手动命名，新分支仍自动叫「星港回声复杂时间线演示」，与既有演示会话十分相似。页面未提供醒目的来源、切点和回到原分支入口，需要在左侧列表辨认。

**代码核对：** Host 已保存 parentSession 和 inheritedEventCount；Client 的 fork 消费主要是管理页内的继承状态通知，没有分支树或同一切点候选切换。创建分支未传标题或主动继承父标题。不能据此断言 DSH 宿主不支持命名；接入方式需再核对公开 API。

**建议：** 增加“来自某剧情 · 第 N 轮”的可点击标识、返回来源、同切点候选切换和可区分的默认标题。已有重生成/编辑重试能力应继续复用；优先补充组织和导航。

## F5 · P2 · 记忆纠错仍面向开发者

**实际：** 从错误事件进入“编辑事件”，首先遇到表名、键、关键词、JSON、时间线数值和事件组 ID。现有记录主要提供删除/原始 JSON，没有“编辑此条并自动带入”的入口。

**建议：** 在事件详情与每条记忆旁增加直接编辑。默认表单显示标题、正文、时间、人物、地点、重要度/召回方式；内部键、JSON 放入高级项。保存后回到原事件，并标示人工修改，以便后台后续整理识别。

**验收：** 普通用户从一条错误记忆出发，不抄写 ID、不手写 JSON，即可修正文案并验证结果。与 F1 可独立实施。

## F6 · P2 · 整理进度缺少可解释的信息

**实际：** 对话回复在 6–10 秒完成；时间线随后长时间只显示“正在整理这轮剧情”，顶部暴露“子代理运行中”。中途核对时原剧情第一轮已提交、第二轮仍运行；收尾复查已显示“已整理 5 个剧情事件 · 完成 2 次记忆整理”，分支也已完成。因此本轮没有后台永久挂起的证据。

**诊断边界：** 原剧情第二轮维护 createdAt 与进入 running 的 updatedAt 相差约 10 分 47 秒，可能包含排队；不能当成纯模型执行耗时。队列没有保留足够的分阶段时间戳，分支 completed 也只有 job ID。浏览器 prompt 阻塞期间无法连续观察，因此不据此宣布后台挂死。

**建议：** 显示“第几轮、等待/整理/重试、已等待多久、已整理到哪轮”；完成记录保留开始/结束和模型信息。提供用户可理解的重试/重新整理入口。模型/详细错误放进展开项；对话可用性与记忆整理状态分别表达。

## F7 · P3 · 开场和配置的日常易用性

- OurNotes 有 26 个开场，原生下拉基本只有编号。支持开场名称、摘要和搜索；与角色卡内可工作的 HTML 线路选择并存。
- 开场本身提示某条特殊路线需要开启世界书条目，但当前 UI 没有开场与依赖条目的关联提示。可以先支持作者填写结构化关联，再提供一键复制本剧情书并启用对应条目，避免要求插件猜测脚本意图。
- 世界书新建使用 `window.prompt`，与其余站内表单不一致。本轮它阻塞了浏览器控制工具，需用户取消；建议改为站内表单以改善焦点、校验和自动化测试，但这属于易用性建议，不能将此次工具超时认作普通用户一定无法创建。
- 左侧“新会话”仍按 DSH 默认回到猫娘模式；已有“用当前角色开启新剧情”藏在角色管理页，可将该入口前移到角色菜单或聊天页。

## 建议实施顺序

1. 修复 fact 正文显示，并补齐分支未完成维护工作的继承。
